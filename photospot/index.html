作例がなくても、
いい景色は
地形から見つかる。

地形と地図のデータから「景色がいい場所」を自動で見つけ、どこに立ち、どちらを向き、いつ撮ればいいかまでスマホで教えるアプリです。誰かが撮った写真に頼らないので、住宅地や郊外でも提案が尽きません。

01 / 見つけた空白

撮影地アプリは、日本とスマホの人に向いていなかった

作り始める前に、国内外のフォトスポット系アプリを15以上調べました。

海外のアプリ

Locationscout、PhotoPills など。カメラ愛好家向けのサブスク（年 数千〜1万円台）が中心で、日本のスポットは少なめ。

国内のアプリ

エビフォト、SNAPLACE、Prism Japan など。2016〜2022年に出たものの、いまも勢いのある専用アプリは見つかりませんでした。

Google マップと Instagram

「場所を保存して地図に出す」ことは無料でできる。ただし、どこからどう撮るかまでは教えてくれません。

どのサービスも「誰かが撮った写真」が出発点です。写真が投稿されていない場所は、どれだけ眺めがよくても地図に出てきません。

02 / 差別化

3つの方針

写真がなくても、地形から見つける

標高・建物・道・樹木・水辺のデータから、眺め・桜・森の小道など7つのテーマで候補を自動で出します。選ばれた理由も「西が開けていて夕日向き」のように文章で示します。

他のアプリ: 投稿された作例が頼り

スマホでの撮り方まで教える

撮る方角をコンパスで、日の入りの時刻と方角を計算で、ズームの倍率や水平線の位置を一言で。前に「当たり」を付けた写真を重ねて同じ構図でも撮れます。

他のアプリ: 光の計画は上級者向けの有料機能

無料で、すぐ使える

ログインなし・広告なし。スポットはアプリに入っていて、電波の弱い山や海辺でも探せます。常時動くサーバーを持たない作りで、運営費を年2〜3万円に抑えます。

他のアプリ: 無料版は制限が多い

03 / 仕組み

スポットを自動で見つける流れ

  1. 歩ける道に点を置く生活道路・遊歩道・階段・山道に約60m間隔で候補地点を置く。高速道路・私道・立入禁止は除く。
  2. 地表の形をつくる地面の標高に、建物の高さ（なければ戸建7m・集合住宅12mと推定）と森（12m）を重ねる。
  3. 360度の見通しを計算する各地点から全方角の見上げ角を求め、遠くまで見渡せる面積、水面の量、富士山やスカイツリーが見える方角を出す。
  4. テーマごとに点数をつける眺めは見通しと高低差、桜・紅葉・花は周囲の樹木の量、森の小道や神秘的な場所は森の割合や社寺・滝・巨木で評価する。
  5. 都県ごとのファイルにしてアプリに入れる重なる地点をまとめ、市区町村ごとの偏りをならしてから書き出す。地図の絞り込みや日の出・日の入りの計算は端末で行う。

04 / 工夫したところ

精度と速さのために直したこと

海沿いばかりが上位に来る

課題最初の採点では、見通しのよい海沿いが上位をほぼ独占し、内陸の眺めや桜の名所が埋もれた。

対応採点を7つのテーマに分け、テーマごとに上位を選ぶ方式に変更。眺めは「海・港」と「内陸」に分けた。

川沿いの低地が「海」になる

課題千葉県では、標高 0.5m 以下を海とみなす判定のせいで、利根川や手賀沼のまわりが海の眺めとして選ばれた。

対応海の判定を標高ではなく、海岸線のポリゴンとの重なりで行うように変更。

都心や湾岸に偏る

課題富士山とスカイツリーが両方見える湾岸の地点が並び、太平洋側や郊外のスポットが押し出された。

対応市区町村ごとに名所クラスの上限（15%）、眺めのテーマは 5km 四方に3か所までに制限。

都県まるごとの計算が重い

課題建物と標高のデータが大きく、東京・神奈川を一度に見通し計算するとメモリも時間も足りない。

対応地域を 16 の区画に分け、のりしろを付けて区画ごとに計算してから都県単位でまとめ直す流れにした。

データを作り直すと記録が消える

課題スポットを計算し直すと ID が変わり、保存した「行きたい場所」や撮影の記録が迷子になる。

対応新旧のスポットが 50m 以内なら同じ ID を引き継ぐようにした。

「梅」が花の名所になる

課題道路名に「梅」が入るだけで花のテーマに入ったり、工業地帯や埋立地が眺めのよい場所に入ったりした。

対応名前の判定を見直し、工業地・埋立地を眺めのテーマから除外。

06 / 機能

初版に入っているもの

  • テーマ・言葉で探す7テーマの絞り込みと、言葉のニュアンス検索・検索履歴
  • 選ばれた理由と360度の見通し見える距離、水面、ランドマークの方角
  • 構図ガイドとカメラコンパス、日の出・日の入り、補助線、前の写真の重ね表示
  • 撮りどきの通知行きたい場所のゴールデンアワー・マジックアワーを知らせる
  • 7日間の天気撮影地点の予報と正確な日の出・日の入り時刻
  • 行きたい場所のリストとメモリスト分け、自分用の撮影地点の調整
  • 写真の保存と共有写真アプリへの保存、LINE・Instagram などへの共有
  • 記録の書き出し機種変更のときに記録と写真をまとめて移せる
  • ダークモードと夜の地図端末の設定に合わせて切り替え
  • 誤りの報告閉鎖・立入禁止などをメールで知らせる
07 / 技術

サーバーを持たない作り

スポットの計算は事前にまとめて行い、結果を都県ごとのファイルとしてアプリに入れています。利用者が増えても費用が増えず、オフラインでも動きます。

アプリ
React Native + Expo SDK 57、画面遷移は expo-router。iOS・Android を1つのコードで。ビルドは EAS。
地図
MapLibre に OpenFreeMap の地図。夜用の配色は自作。ピンはテーマごとにまとめて表示。
スポットの計算
Python。地域を区画に分けて並列に計算し、都県ごとにランキング。標高は Mapzen の地形タイル、建物・道・水辺は Overture Maps。
端末での計算
日の出・日の入り（suncalc）、方角と距離、撮りどきの判定。天気だけ Open-Meteo から取得。
08 / 進め方

AI と分担して、判断は自分で

開発には AI コーディングアシスタントの Claude を使いました。機能ごとに作業を分けて変更をプルリクエストで受け取り、画面で確かめてから取り込む進め方です。

自分が担当したこと

誰に向けて何を作るかの決定、仕様と優先順位、試作結果のストリートビューでの確認、画面の使い勝手の指摘、変更の確認と取り込み、公開までの計画。

AI に任せたこと

競合とデータの調べもの、計算処理とアプリのコードの実装、画面のプレビュー作成。出てきた案や結果は、採るかどうかを自分で決めました。

対象を「スマホで撮る一般の人」に絞った
カメラ愛好家向けは海外の有料アプリが強い。日本の一般ユーザー向けには、定着したアプリが見当たらなかった。
写真の投稿と共有を初版から外した
ログインとサーバーが必要になり、公開が遅れて費用もかかる。まずは一人で使って価値が出る形で出す。
AI による意味検索ではなく、言葉の辞書で探す方式にした
端末に AI モデルを入れるとアプリが重くなり、サーバーで動かすと費用がかかる。「無料・サーバーなし」の方針を優先した。
夜の地図の配色を作り直した
既製のダーク地図は黒すぎると感じたので、昼の地図の配色をもとに夜用を作り直してもらった。
Android を先に、初版は広告なしで出す
Google Play の公開条件（テスターの期間）を先に満たし、反応を見てから iOS と収益化を考える。
