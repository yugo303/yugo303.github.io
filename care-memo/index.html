01

現場で足りなかったこと

↑ 目次へ

介護の業界は IT の活用が遅れていると感じていました。介護士に比べて注目されにくいケアマネジャーの仕事に課題があるのではと考え、現役のケアマネジャーに業務の流れと困りごとを聞きました。

ケアマネジャーは利用者のお宅で聞いた内容を、事業所に戻ってから介護ソフトの支援経過に書き起こします。ほのぼのには外出先で使えるオプションがありますが追加の料金がかかり、事業所の費用の面から導入できないことがあります。そのため、メモと記憶を頼りに、戻ってからまとめて入力することになります。

完成したソフトでも、現場の人が使えて初めて意味がある。インタビューから得た気づき

話を聞くと、似た機能のソフトはすでに市場にあることも分かりました。足りないのは機能ではなく、事業所に新しい仕組みを入れる余力（お金・手間・慣れ）でした。そこで方針を変えました。

最初の考え新しい技術や AI を使った便利なソフトを作って渡す
→
変えたあと導入の余力がない事業所でも、今の仕事にそのまま足せるものを作る
02

3つの方針

↑ 目次へ

ほのぼのの代わりにしない

事業所の介護ソフトはそのまま使い続けられるようにし、このアプリは「外で話したことを事業所に届ける」だけにしました。パソコン側に必要なのはブラウザとカメラだけです。

記録をサーバーに残さない

利用者の個人情報を扱うので、音声や記録はサーバーに保存せず、まとめ終わったら捨てる作りにしました。下書きはスマホの中だけに残ります。ログインもありません。

AI を使ったことがない人でも迷わない

使う人はデジタルに慣れていない年配の方が多いと考え、カタカナや IT の言葉を避け、次にどこを押すかを画面がいつも教えるようにしました。

03

使い方と仕組み

↑ 目次へ
  1. 1話す青いボタンを押して話すと、その場で文字になります。途中で画面を閉じても消えません。
  2. 2まとめる緑のボタンで、AI が「本人の様子・主訴／事実・対応／特記事項・方針」の3つに整えます。各欄は手で直せます。
  3. 3パソコンへスマホに出た QR コードを事業所のパソコンのカメラで読み取り、1欄ずつコピーしてほのぼのに貼ります。
約0.3〜0.5円 / 1回

AI でまとめる1回あたりの費用です。軽くて安いモデルを選び、呼ばれたときだけ動く仕組みにしました。

0件

サーバーに保存する記録の数です。データベースは持たず、まとめた結果は返したら残しません。

2画面

スマホ用と、パソコンで受け取る用の2つだけです。事業所でソフトを入れる必要はありません。

スマホとパソコンはネットワークでつながず、QR コードを画面に映すだけで受け渡します。事業所のネットワークの設定を変えずに使えるようにするためです。

04

工夫したところ

↑ 目次へ

言葉が難しい

課題「整形」「認識」「エラー」のような言葉や、ファイル名がそのまま画面に出ていました。

対応「録音は止まっています」「記録の形にまとめる」のように、そのまま行動につながる言い方に書き直しました。

次にどこを押すか迷う

課題機能は動いても、初めての人には何から始めて、どこで終わるのかが分かりにくい画面でした。

対応「① 話す → ② まとめる → ③ パソコンへ」を上にいつも出し、次に押すボタンを黄色の吹き出しで示すようにしました。

録音を止めたあと手が止まる

課題話し終わったあと、まとめるボタンまでたどり着かずに終わってしまうことが考えられました。

対応録音を止めて8秒たつと「まとめますか？」とふきだしで聞くようにしました。すぐ出すと話の途中で邪魔になるので、間をとっています。

長く話すと途中で切れる

課題スマホの音声入力は、しばらく話すと勝手に止まります。画面が暗くなっても止まります。

対応切れたら自動でつなぎ直し、文字は随時スマホに保存するようにしました。録音中は画面が暗くならないようにしています。

QR コードで日本語が化ける

課題日本語をそのまま QR コードにすると、パソコン側で読み取ったときに文字が化けることがありました。

対応文字を英数字の形（Base64）に変えてから QR コードにし、受け取る画面で元に戻すようにしました。

直しても画面が新しくならない

課題ホーム画面に追加したアプリが古い画面を覚えていて、改良がなかなか届きませんでした。

対応画面は毎回ネットから取り、つながらないときだけ保存しておいた画面を出すようにしました。

06

機能

↑ 目次へ
  • 長い時間の音声入力切れても自動で再開、文字数と録音時間の表示
  • 下書きの自動保存画面を閉じても、話した内容とまとめた結果が残る
  • AI で3つの欄にまとめる本人の様子・主訴／事実・対応／特記事項・方針
  • 結果を手で直せる直した内容は QR コードにも反映
  • QR コードでパソコンへパソコン側は受け取り用の画面を開くだけ
  • 欄ごとのコピースマホでもパソコンでも1欄ずつコピー
  • 案内とふきだし次に押すボタンの表示、録音停止後の声かけ
  • 使い方の説明初回に自動で表示、「使い方」ボタンでいつでも見直せる
  • ホーム画面に追加アプリのように起動でき、画面が暗くならない
  • やさしいお知らせ電波がないときなど、次にどうすればよいかを伝える
07

技術と構成

↑ 目次へ

現場のスマホは機種もブラウザもさまざまなので、フレームワークを使わず、画面ごとに1つのファイルで動くようにしています。サーバーは呼ばれたときだけ動く仕組みにして、使わない月の費用がほとんどかからないようにしました。

スマホの画面
HTML / CSS / JavaScript の1ファイル。音声入力は Web Speech API、画面を暗くしないのは Screen Wake Lock API、QR コードは qrcode-generator です。
アプリとして使う
manifest.json と Service Worker でホーム画面に追加できる PWA にしています。公開は Vercel です。
AI でまとめる
AWS Lambda（Node.js）と API Gateway の HTTP API で受け、Amazon Bedrock の Claude Haiku 4.5 で3つの欄に整えます。
パソコンの受け取り画面
html5-qrcode でパソコンのカメラから QR コードを読み取り、欄ごとに分けて表示します。
08

開発の進め方

↑ 目次へ

最初の試作は AI の Gemini に相談しながら作り、2026年10月からは AI コーディングアシスタントの Claude で改良を続けています。変更はプルリクエストで受け取り、スマホの実機で確かめてから取り込んでいます。

自分が担当したこと

現場の課題探しとケアマネジャーへのインタビュー、何を作り何を作らないかの決定、AWS の構成と構築（API Gateway・Lambda・Bedrock の設定）、使う人を考えた言葉や導線の指摘、実機での動作確認、変更を取り込むかどうかの判断を担当しました。

AI に任せたこと

画面のコードの実装と作り直し、使い方の説明のアニメーション、不具合の原因の調査を任せました。出てきた案を採用するかどうかは、自分で決めています。

ほのぼのとの自動連携を作らなかった
連携には事業所側の設定や費用が必要になり、「導入の余力がない」という本当の課題に逆らうためです。コピーと貼り付けで済む形にしました。
利用者ごとの記録の管理を持たなかった
個人情報を保存すると、管理の責任と導入のハードルが上がります。記録を書く手間を減らす一点にしぼりました。
録音停止の8秒後に「まとめますか？」と聞く
自分で出した案です。最初はもう少し長い間でしたが、8秒に縮めました。表示のときに画面が勝手に動かないようにもしています。
メールで送るボタンは見送った
共有の手段としてワンボタンのメール送信も考えましたが、まずは QR コードでの受け渡しを使いやすくすることを優先しました。
文字は大きく、言葉はやさしく
使う人はデジタルに慣れていない年配の方が多いと考え、本文は17px 以上、ボタンは大きく、「パソコン」のように普段の言葉を使うことにしました。
